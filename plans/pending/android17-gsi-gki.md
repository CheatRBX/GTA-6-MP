# План: своя ОС на Android 17 (GSI) + ядра GKI с поддержкой USB Wi‑Fi

Статус: **черновик, ждёт одобрения**. Трекер задач: GitHub Issues (заводим все задачи сразу после одобрения).
Рабочее название ОС: `<ИМЯ_ОС>` (вопрос 1).

---

## 0. Честно о границах: что физически возможно

| Желание | Реальность (проверено) | Что делаем вместо |
| --- | --- | --- |
| Одно ядро для **всех** устройств | Невозможно. Ядро зависит от процессора (SoC), загрузчика и драйверов производителя. Даже у Google GKI — это одно ядро **на каждую ветку KMI** (`android14-6.1`, `android15-6.6`, `android16-6.12`, `android17-6.18`), и оно подходит только устройствам, вышедшим с этой веткой. Модули между ветками несовместимы. Устройства на ядрах 4.x и 5.4 GKI не поддерживают вообще. | Линейка ядер: свой `boot.img` на каждую ветку KMI. |
| Единый GSI для всех | Возможно в рамках Project Treble: один `system.img` для arm64‑устройств с Treble. Ядро и vendor остаются от производителя, поэтому камера, VoLTE, отпечаток или NFC на отдельных моделях могут не работать. | GSI на базе LineageOS 24 (Android 17) + патчи TrebleDroid, правки под модели по отчётам. |
| «Чтобы не ломались» | Гарантировать это не может никто, даже Google. | Гарантируем процесс: QA каждой сборки в эмуляторе, тест на реальных телефонах, бэкап стокового `boot`/`vbmeta`, инструкция отката, бета‑канал. |
| USB Wi‑Fi (rtl8822bu и т.д.) | Драйвер `rtw88_8822bu` есть в Linux с 6.2. Проверка исходников Google: в `android15-6.6`, `android16-6.12` и `android17-6.18` он есть, в `android14-6.1` нет (нужен бэкпорт). В `6.18` также есть 8821AU, 8812AU и 8814AU. **Риск 1:** в GKI 6.x `cfg80211`/`mac80211` не встроены в ядро (`gki_defconfig` их не включает), поэтому наши модули должны совпасть с Wi‑Fi‑стеком конкретного устройства. **Риск 2:** Android сам по себе показывает в Настройках только встроенный Wi‑Fi (`wlan0`); USB‑адаптер (`wlan1`) без доработки системы там не появится. | Фаза 0 проверяет это на реальном телефоне **до** основной работы. |
| Сборка | По требованиям Google для Android 17 нужно от ~400 ГБ диска и 64 ГБ ОЗУ. Этот облачный контейнер: 4 ядра, 15 ГБ ОЗУ, 60 ГБ, без KVM. | Ядра и модули собираем в GitHub Actions, ОС — на отдельном сервере. |
| QA в эмуляторе (плагин `android-emulator-qa`) | Эмулятору нужен KVM; в этом контейнере его нет (`/dev/kvm` отсутствует, `adb` не установлен). Эмулятор не проверяет реальное железо: камеру, модем, USB Wi‑Fi. | Собираем вариант ОС для эмулятора (x86_64) и гоняем сценарии плагина на сервере сборки или в GitHub Actions (там есть KVM). Железо проверяем на реальных телефонах. |

## 1. Архитектура проекта

```
os/                    манифест (local_manifests), скрипты сборки ОС
  vendor/<имя>/        брендинг: имя, версия, bootanimation, обои, «О телефоне», оверлеи
  patches/             патчи TrebleDroid + наши
kernel/                фрагменты конфигов и скрипты сборки custom GKI по веткам, AnyKernel3
modules/usb-wifi/      сборка rtw88 (8822bu, 8821cu, 8822cu, 8812au, 8821au …) + прошивки + загрузчик
qa/                    сценарии эмулятор-QA (плагин), чек-лист проверки телефона, скрипт снимка устройства
device-reports/        отчёты по устройствам (что работает / что нет)
docs/                  установка, откат, список устройств
.github/workflows/     CI: ядра, модули, эмулятор-QA
```

Что выходит в каждом релизе:
- `<имя>-24.0-ГГГГММДД-arm64-bvN.img.xz` — ОС без Google‑приложений (позже `bgN` — с GApps);
- `<имя>-kernel-<ветка>-ГГГГММДД.zip` — ядро для прошивки через AnyKernel3, по одному на ветку KMI;
- `<имя>-usbwifi-<ветка>.zip` — пакет драйверов USB Wi‑Fi (KernelSU/Magisk‑модуль, работает и на стоковой прошивке);
- `SHA256SUMS` для всех файлов.

## 2. Фазы

### Фаза 0: проверка рисков (до любой большой работы)
Готово, когда: на тестовом телефоне адаптер rtl8822bu видит сети (`iw dev wlan1 scan`), чистая база ОС собрана на сервере, эмулятор с KVM запускается и виден плагину.
Файлы: `kernel/scripts/*`, `qa/probe.sh`, `.github/workflows/modules.yml`, `device-reports/`

#### Шаг 0.1: сборка модулей rtw88 USB под ветку тестового телефона (Size: S)
- Критерии: модули собираются в CI; есть отчёт о символах, которых нет в экспорте релизного GKI.
- Проверка: `./kernel/scripts/build-modules.sh <ветка> && ./kernel/scripts/check-symbols.sh out/<ветка>`
- Файлы: `kernel/scripts/build-modules.sh`, `kernel/scripts/check-symbols.sh`, `.github/workflows/modules.yml`
- Где доказывается: вывод modpost + сравнение с `vmlinux.symvers` релизного GKI
- Блокеры: вопросы 3 и 6

#### Шаг 0.2: снимок тестового телефона (Size: XS)
- Критерии: в репозитории есть `device-reports/<модель>.txt`: версия ядра, ветка KMI, Treble/VNDK, A/B, версия заголовка boot, список модулей vendor, есть ли `cfg80211.ko`/`mac80211.ko`.
- Проверка: `adb push qa/probe.sh /data/local/tmp/ && adb shell sh /data/local/tmp/probe.sh > device-reports/<модель>.txt` (запускаете вы, на своём ПК)
- Файлы: `qa/probe.sh`
- Блокеры: вопрос 3

#### Шаг 0.3: загрузка модулей на телефоне (Size: S)
- Критерии: `dmesg` без ошибок символов; `iw dev` показывает `wlan1`; сканирование находит сети; встроенный Wi‑Fi продолжает работать.
- Проверка: `adb shell su -c 'sh /data/local/tmp/usbwifi-load.sh && iw dev wlan1 scan | head'`
- Блокеры: 0.1, 0.2

#### Шаг 0.4: сервер сборки (Size: S)
- Критерии: синхронизированы исходники LineageOS 24 + TrebleDroid; чистый GSI‑таргет собран без изменений; время сборки замерено.
- Проверка: `./os/build.sh --variant bvN --clean-base` → `system.img` (путь к артефакту уточняется на шаге)
- Блокеры: вопрос 5

#### Шаг 0.5: эмулятор с KVM (Size: XS)
- Критерии: установлены Android SDK cmdline‑tools + emulator; стоковый образ Android 17 загружается; плагин видит устройство и снимает скриншот.
- Проверка: `python3 <плагин>/scripts/android-qa.py devices` и `android-qa.py screenshot --serial <serial> --out qa-output/boot.png`
- Блокеры: вопрос 5

### Фаза 1: каркас репозитория и брендинг
Готово, когда: структура из раздела 1 закоммичена, бренд подключён к сборке.

#### Шаг 1.1: структура репозитория и документация (Size: S)
- Критерии: README, LICENSE (Apache‑2.0 для нашего кода), NOTICE (GPL для ядра), `docs/install.md`, `docs/rollback.md` с бэкапом стокового `boot`/`vbmeta`.
- Проверка: `ls os kernel modules qa docs && markdownlint docs/`
- Блокеры: вопросы 1 и 6

#### Шаг 1.2: брендинг `os/vendor/<имя>` (Size: S)
- Критерии: в «О телефоне» наше имя и версия; своя загрузочная анимация и обои; нигде нет логотипов и названия LineageOS (требование их товарного знака).
- Проверка: `grep -ri lineage os/vendor/<имя>/` ничего не находит в видимых строках; сценарий QA 2.3 видит имя в «О телефоне».
- Блокеры: 1.1, 0.4

#### Шаг 1.3: скрипт сборки ОС (Size: S)
- Критерии: один скрипт делает синхронизацию, накладывает патчи, собирает, сжимает `.img.xz` и считает SHA256.
- Проверка: `./os/build.sh --variant bvN`
- Блокеры: 0.4

### Фаза 2: первая сборка ОС и QA
Готово, когда: GSI загружается на тестовом телефоне и проходит эмулятор‑QA.

#### Шаг 2.1: GSI arm64 `bvN` с брендом (Size: S)
- Критерии: собирается; образ помещается в раздел `system` телефона.
- Проверка: `./os/build.sh --variant bvN`
- Блокеры: 1.2, 1.3

#### Шаг 2.2: та же ОС для эмулятора x86_64 (Size: S)
- Критерии: эмуляторный таргет собирается из того же `vendor/<имя>` и загружается в эмуляторе.
- Проверка: `./os/build.sh --variant emulator && ./qa/start-emulator.sh` → `adb shell getprop sys.boot_completed` = `1`
- Блокеры: 2.1, 0.5

#### Шаг 2.3: сценарии плагина `android-emulator-qa` (Size: M)
- Критерии: (1) загрузка завершена, в `logcat -b crash` нет падений; (2) «Настройки → О телефоне» показывает имя и версию ОС; (3) виртуальный Wi‑Fi подключается, тестовый APK ставится и запускается.
- Проверка: `./qa/run-emulator-qa.sh <serial>`: внутри шаги плагина `dump-ui` → `summarize-ui` → `pick --target "О телефоне"` → `input tap` → `screenshot` → `logcat`. Доказательства (скриншоты, UI‑сводки, логи) кладутся в `qa-output/`.
- Файлы: `qa/run-emulator-qa.sh`, `qa/flows/*.sh`
- Блокеры: 2.2

#### Шаг 2.4: проверка на реальном телефоне (Size: S)
- Критерии: заполнен чек‑лист `qa/device-checklist.md`: загрузка, звонки, SMS, мобильный интернет, Wi‑Fi, Bluetooth, камера, звук, отпечаток, GPS, зарядка, сон.
- Проверка: результат в `device-reports/<модель>.md` (прошиваете и проверяете вы, я разбираю логи)
- Блокеры: 2.1

### Фаза 3: линейка ядер (custom GKI)
Готово, когда: наше ядро загружается на тестовом телефоне, встроенный Wi‑Fi и модем работают, USB Wi‑Fi работает.

#### Шаг 3.1: ядро для ветки тестового телефона + AnyKernel3 (Size: M)
- Критерии: исходники ACK на теге релиза GKI телефона; `gki_defconfig` + наш фрагмент: экспорт символов для модулей, rtw88 USB модулями; KMI не меняем, чтобы модули производителя грузились. Телефон загружается, `uname -r` с нашим суффиксом.
- Проверка: артефакт `.github/workflows/kernels.yml` + отчёт о загрузке в `device-reports/`
- Блокеры: 0.3

#### Шаг 3.2: остальные ветки 6.x (Size: S каждая)
- Критерии: `android17-6.18`, `android16-6.12`, `android15-6.6` собираются тем же скриптом.
- Проверка: `./kernel/scripts/build-kernel.sh <ветка>` для каждой ветки в CI
- Блокеры: 3.1

#### Шаг 3.3: `android14-6.1` с бэкпортом rtw88 USB (Size: M), по запросу
- Блокеры: 3.2

### Фаза 4: USB Wi‑Fi в ОС
Готово, когда: адаптер работает в нашей ОС без ручных команд (объём зависит от вопроса 4).

#### Шаг 4.1: модули и прошивки в GSI с автозагрузкой (Size: S)
- Критерии: прошивки в `/system/etc/firmware/rtw88/`; модули под каждую ветку KMI; при подключении адаптера init‑сервис грузит набор под `uname -r`; есть правила SELinux.
- Проверка: подключить адаптер → `adb shell iw dev` показывает `wlan1` без ручных команд
- Блокеры: 3.1

#### Шаг 4.2a: режим монитора/пентеста (Size: S), если вопрос 4 = a или c
- Критерии: в комплекте `iw`, `tcpdump` и набор aircrack‑ng; режим монитора включается.
- Проверка: `iw dev wlan1 set type monitor && iw dev wlan1 info`

#### Шаг 4.2b: обычный интернет через USB‑адаптер (Size: L → разбить на месте), если вопрос 4 = b или c
- Направление: системное приложение со своим `wpa_supplicant` + DHCP, которое отдаёт сеть в Android через `NetworkAgent`; свой экран выбора сети. Детали — туман, исследуем на старте фазы.

## 3. Журнал решений (предложено, ждёт подтверждения)

| Решение | Выбор | Почему |
| --- | --- | --- |
| База ОС | LineageOS 24.0 + патчи TrebleDroid | Готовые функции (обновления, приватность, настройки) и ежемесячные патчи безопасности; сообщество уже собирает Android 17 GSI на этой базе, путь проверен. Нужно переименование (товарный знак Lineage). |
| Архитектура | только arm64, A/B (system‑as‑root) | A‑only и 32‑бит практически вымерли для GSI на Android 12+. |
| Ядра | своё GKI на каждую ветку KMI | Модули между ветками несовместимы (документация Google). |
| Доставка USB Wi‑Fi | модули под каждую ветку: внутри нашего GSI + отдельный KernelSU/Magisk‑модуль | Работает и без прошивки нашего ядра, если символы позволяют (это проверяет фаза 0). |
| QA | эмулятор (плагин) для софта, реальные телефоны для железа | Эмулятор не видит камеру, модем и USB‑адаптер. |
| Сборка | GitHub Actions для ядер, отдельный сервер для ОС | Размер исходников и требования к ОЗУ у Android. |

## 5. Всегда / никогда
- **Всегда:** код открыт на GitHub; исходники ядра публикуются (требование GPL); каждый релиз проходит эмулятор‑QA и хотя бы один реальный телефон; к каждому релизу есть инструкция установки и отката и контрольные суммы.
- **Никогда:** не обещаем «работает на всех устройствах»; не используем логотипы и названия LineageOS/Android как свой бренд; не вшиваем Google‑приложения в основной образ; не работаем с ядрами 4.x; не пушим в ветки кроме рабочей.
- **Вне объёма:** обход Play Integrity и подмена сертификации, x86/32‑бит телефоны, одно ядро на все устройства.
