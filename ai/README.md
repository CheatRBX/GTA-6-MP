# ◆ Corax LM — своя нейросеть с нуля для телефона

Своя языковая модель (как ChatGPT, только маленькая), написанная **с нуля** и работающая **офлайн прямо на телефоне в Termux**.

Здесь нет чужих готовых моделей и тяжёлых библиотек:
- **свой токенизатор** (BPE) — учится на твоих текстах;
- **своя архитектура** трансформера, как у современных LLM: RMSNorm, RoPE, GQA-внимание, SwiGLU;
- **своё обучение на C**: прямой и обратный проход, AdamW. Работает прямо в Termux, PyTorch не нужен;
- **дообучение** на своих диалогах (SFT): модель учится отвечать как ассистент;
- **квантование** q8 (в 3,5 раза меньше) и q4 (в 6 раз меньше);
- **быстрый движок на C**: инструкции ARM NEON dotprod, многопоточность с выбором больших ядер Snapdragon, KV-кеш в fp16, mmap;
- **чат в стиле терминальных ИИ-ассистентов**: строка состояния со скоростью (ток/с), видно, что модель сейчас делает: читает запрос или генерирует ответ.

Нужны только `clang`, `make` и `python` — всё ставится одной командой.

---

## Чего ожидать честно

Модель учится **с нуля**, поэтому её ум зависит от трёх вещей: **размер**, **объём текстов** и **время обучения**.

| Пресет | Параметров | Файл q8 / q4 | Скорость на Snapdragon 7 Gen 3* | Где обучать |
|---|---|---|---|---|
| `nano`   | 6,5 млн  | 7 / 4 МБ     | 300+ ток/с | телефон: ~30–45 минут |
| `mini`   | 16 млн   | 17 / 9 МБ    | 200+ ток/с | телефон: несколько часов |
| `small`  | 33 млн   | 36 / 20 МБ   | 120–200 ток/с | телефон: ночь и больше |
| `medium` | 82–88 млн | 88–95 / 49–53 МБ | **~70–110 ток/с** | ПК или бесплатный Google Colab |
| `large`  | 190–197 млн | — / 113–118 МБ | 40–60 ток/с (q4) | ПК с видеокартой |

\* Скорость — **оценка** по пропускной способности памяти LPDDR4X, на реальном телефоне не замерялась. Точную цифру для своего телефона покажет команда `./corax bench`, подробнее в разделе «Скорость».

**Под цель «~70 ток/с и как можно умнее» подходит `medium` в q8 или q4.** Обучить его с нуля на самом телефоне слишком долго (недели), поэтому базовую модель лучше учить на ПК или в Colab, а на телефоне дообучать и запускать (см. «Обучение на ПК / Colab»). Модели `nano`, `mini` и `small` спокойно учатся прямо на телефоне.

**Насколько она будет умной.** Модель на 30–90 млн параметров после хорошего обучения пишет связный текст по-русски, держит тему, отвечает в стиле твоих диалогов, запоминает факты из дообучения и придумывает рассказы. Хорошо обученный `medium` — это примерно уровень GPT-2 small (124 млн параметров), модели поменьше проще. Но это **не Claude и не ChatGPT**: у них в тысячи раз больше параметров и данных, и учат их на тысячах видеокарт. Логику, математику и точные факты маленькая модель знает слабо и часто выдумывает. Как сделать её умнее — в разделе «Как сделать модель умнее».

## Быстрый старт в Termux

1. Установи **Termux** с [F-Droid](https://f-droid.org/packages/com.termux/) или со страницы [GitHub Releases](https://github.com/termux/termux-app/releases). Версия из Google Play часто устаревшая.
2. В Termux:

```bash
pkg install -y git
git clone https://github.com/CheatRBX/GTA-6-MP.git
cd GTA-6-MP/ai
bash scripts/setup_termux.sh      # ставит clang/make/python и собирает ./corax
bash scripts/quickstart.sh        # данные → токенизатор → обучение → дообучение → q8 → бенчмарк
./corax chat -m models/chat-q8.bin
```

`quickstart.sh` по умолчанию учит `nano` за 1500 шагов (~30–45 минут на Snapdragon 7 Gen 3). Дольше учится — лучше пишет: `STEPS=3000 bash scripts/quickstart.sh`. Модель побольше:

```bash
PRESET=small STEPS=6000 bash scripts/quickstart.sh
```

**Ctrl+C — это пауза, а не потеря:** модель сохраняется сразу после текущего шага, повторный запуск того же скрипта **продолжит с этого места**. Уже обученное (токенизатор, данные, готовые этапы) заново не делается.

**Модель для чата (`models/chat-q8.bin`) появляется только в конце скрипта.** Пока идёт обучение, можно посмотреть, чему модель уже научилась: `./corax gen -m models/base.bin -p "Однажды"` (модель сохраняется каждые 200 шагов и при паузе).

> Во время долгого обучения выполни `termux-wake-lock`, чтобы Android не усыплял Termux. Положи телефон на прохладную поверхность: при перегреве процессор сбрасывает частоту.

## Пошагово (если хочется понимать, что происходит)

### 1. Данные

Модель учится предсказывать следующий кусочек текста. Чем больше хорошего текста, тем умнее модель.

```bash
bash scripts/get_data.sh ru-stories      # ~5 тыс. рассказов на русском и английском (19 МБ, CC-BY-SA-4.0)
bash scripts/get_data.sh tinystories     # TinyStories, английский, ~20 МБ
```

**Свои тексты** подходят любые: книги, статьи, переписки, код. Положи файлы `.txt` или `.jsonl` (с полем `"text"`) в `data/raw/`. Документы в `.txt` разделяй строкой `<|endoftext|>`, если она есть; если нет, файл считается одним длинным текстом.

### 2. Токенизатор и подготовка

```bash
python3 tools/prepare.py pretrain data/raw --out-dir data --vocab 8192 --min-cyr 0.5
```

- обучает **свой BPE-токенизатор** (`data/tokenizer.bin`), если его ещё нет;
- превращает тексты в токены: `data/train.bin` и `data/val.bin` (1% на проверку);
- `--min-cyr 0.5` оставляет только русские тексты (доля кириллицы ≥ 50%); без него берутся все;
- `--vocab`: 8192 подходит для nano/mini/small, для medium/large бери 16384.

Отдельно токенизатор можно обучить так: `python3 tools/tokenizer.py data/raw --vocab 8192 --out data/tokenizer.bin`.

### 3. Обучение с нуля

```bash
./corax train --preset small --data data/train.bin --val data/val.bin \
    --tokenizer data/tokenizer.bin --out models/base.bin --steps 6000
```

Во время обучения внизу обновляется одна строка: полоска прогресса, шаг, **loss** (ошибка, должна падать), скорость в ток/с и сколько осталось. Каждые 200 шагов программа проверяет модель на валидации (строка `▸`), пишет пример текста и сохраняет модель. Перед стартом она сама замеряет, что быстрее — только большие ядра или все, и берёт лучшее.

| Параметр | Что делает | По умолчанию |
|---|---|---|
| `--preset` | размер: nano / mini / small / medium / large (`./corax presets`) | nano |
| `--steps` | сколько шагов учиться | 2000 |
| `--batch`, `--seq` | последовательностей за шаг и их длина | ~2048 токенов на шаг |
| `--accum` | накопление градиента (большой батч без лишней памяти) | 1 |
| `--lr` | скорость обучения | 1e-3 (nano/mini), 6e-4 (остальные) |
| `--resume` | продолжить с места остановки после Ctrl+C (нужен файл `models/base.bin.opt`) | — |
| `--sample-prompt` | с чего начинать пример текста | — |
| `-t` | число потоков | подбирается само (большие ядра или все — что быстрее) |

**Как понять, что обучение идёт хорошо.** Loss быстро падает с ~9 до ~5, дальше медленнее. На валидации важна **перплексия**: чем ниже, тем лучше; для связного текста нужно меньше ~20–30. Если loss на обучении падает, а на валидации растёт, модель зазубривает: нужно больше данных или меньше шагов.

**Сколько шагов.** Хорошее правило: модель должна увидеть примерно **20 токенов на каждый параметр**. Для `small` (33 млн) это ~660 млн токенов. За один шаг модель видит ~2048 токенов, так что на тех же данных можно делать несколько проходов (эпох).

Сколько памяти займёт обучение, программа пишет при старте. Если Android убивает процесс (`Killed`), уменьши `--batch` и увеличь `--accum`.

### 4. Дообучение (SFT) — учим отвечать как ассистент

Базовая модель умеет только продолжать текст. Чтобы она **отвечала на вопросы**, её дообучают на диалогах. Пример лежит в `data/sft_example.jsonl` — 290 диалогов: модель представляется как Corax, отвечает на приветствия (в том числе «hi», «ку», «чё?»), благодарности, грубости и простые вопросы. Добавляй свои.

Формат: одна строка — один диалог (JSONL). Поддерживаются популярные форматы:

```json
{"messages": [{"role": "user", "content": "Привет!"}, {"role": "assistant", "content": "Привет! Чем помочь?"}]}
{"messages": [{"role": "system", "content": "Ты пират."}, {"role": "user", "content": "Кто ты?"}, {"role": "assistant", "content": "Я капитан Corax, гроза семи морей!"}]}
{"instruction": "Переведи на английский", "input": "кошка", "output": "cat"}
{"prompt": "Сколько будет 2+2?", "response": "4"}
{"conversations": [{"from": "human", "value": "Привет"}, {"from": "gpt", "value": "Здравствуй!"}]}
```

```bash
python3 tools/prepare.py sft data/sft_example.jsonl мои_диалоги.jsonl --tokenizer data/tokenizer.bin --out data/sft
./corax finetune --model models/base.bin --data data/sft --out models/chat.bin --steps 600
```

- модель учится **только на ответах ассистента**: вопросы она видит, но не заучивает (маска);
- `--steps 300–2000`, `--lr` по умолчанию 2e-4. На примерах из комплекта модель в основном заучивает ответы и на новые вопросы отвечает заученным. Чтобы она отвечала своими словами, нужны сотни и тысячи разных диалогов. Если на большом наборе ответы повторяют обучающие слово в слово, шагов слишком много;
- если в диалогах есть системная подсказка (`system`), в чате передай ту же самую: `--system "..."`;
- **дообучение на текстах** (например, книги по нужной теме) работает так же: `--data data/train.bin` вместо `data/sft`.

Дообучение можно повторять сколько угодно раз: оно берёт f32-модель и выдаёт новую f32-модель.

### 5. Квантование

```bash
./corax quantize models/chat.bin models/chat-q8.bin q8   # ~3,5x меньше, качество почти не меняется
./corax quantize models/chat.bin models/chat-q4.bin q4   # ~6x меньше, чуть хуже качество, лучше для больших моделей
```

Квантование хранит веса группами по 32 числа: 8 или 4 бита на число плюс масштаб группы. Активации на лету тоже переводятся в int8, и умножение идёт целыми числами инструкцией ARM `sdot`. Это главный ускоритель на телефоне. **Учить и дообучать** можно только f32-файл (тот, что до `quantize`), поэтому храни его.

### 6. Чат

```bash
./corax chat -m models/chat-q8.bin
./corax chat -m models/chat-q8.bin --temp 0.7 --system "Ты весёлый помощник." -t 4
```

Так выглядит интерфейс (ответ и цифры здесь для примера):

```
╭────────────────────────────────────╮
│ ◆ Corax LM                         │
│ своя нейросеть · офлайн · с нуля   │
╰────────────────────────────────────╯
◆ Corax LM  chat-q8.bin
  33.2 млн параметров · q8 · веса 35.7 МБ · контекст 512

❯ Привет! Кто ты?
● Привет! Я Corax — небольшая нейросеть, обученная с нуля...
  └ 24 ток · 156.3 ток/с · чтение 9 ток за 0.05с · контекст 41/512

 ◆ жду ввода │ 156 ток/с │ 41/512
```

Внизу экрана **строка состояния** (на широком экране подробнее: размер модели, квантование, потоки): что модель делает (`читаю запрос`, `генерирую`, `жду ввода`), текущая скорость в ток/с и заполненность контекста. После каждого ответа выводится статистика.

Команды в чате: `/help`, `/reset` (забыть разговор), `/system ТЕКСТ`, `/temp 0.7`, `/topp 0.9`, `/topk 40`, `/rep 1.1`, `/stats`, `/info`, `/exit`. **Ctrl+C** во время ответа останавливает генерацию. Строка с `\` в конце переносится.

Флаги: `--temp` (0 = всегда самый вероятный ответ), `--top-p`, `--top-k`, `--rep` (штраф за повторы), `--ctx N` (ограничить контекст), `--seed`, `--no-bar` (без строки состояния), `--no-color`.

Продолжение текста для базовой модели: `./corax gen -m models/base.bin -p "Однажды в лесу" -n 200`.

## Скорость

```bash
./corax bench -m models/chat-q8.bin            # скорость генерации и чтения промпта
./corax bench -m models/chat-q8.bin --sweep    # перебор числа потоков — найдёт лучшее для твоего телефона
```

**Почему быстро:**
- **q8/q4 + NEON dotprod**: умножение целых 8-битных чисел, по 16 штук за инструкцию;
- **большие ядра**: программа читает частоты ядер, по умолчанию берёт только быстрые (у SD 7 Gen 3 их 4: 1×2,63 + 3×2,4 ГГц) и закрепляет за ними потоки;
- **динамическая раздача работы**: быстрые ядра забирают больше, медленные не тормозят остальных;
- **слияние операций**: q/k/v считаются одним заданием, SwiGLU прямо внутри умножения;
- **KV-кеш в fp16**: вдвое меньше чтения памяти на длинном контексте;
- **mmap**: модель открывается мгновенно и не копируется в память.

**Откуда оценка ~70+ ток/с.** Генерация упирается в скорость памяти: на каждый токен нужно прочитать все веса. LPDDR4X на SD 7 Gen 3 даёт процессору примерно 15–20 ГБ/с. Значит, `medium` в q8 (~90 МБ) упирается в ~150–200 ток/с, а с учётом накладных расходов получается порядка 70–110 ток/с. `small` (36 МБ) — заметно быстрее. Реальную цифру покажет `bench`.

**Советы:** `termux-wake-lock`, не держи телефон в чехле при долгой работе, попробуй `--sweep`. Иногда 5–6 потоков быстрее 4.

## Обучение на ПК / Google Colab (для medium и large)

Тот же формат модели, та же архитектура. На видеокарте обучение идёт в десятки раз быстрее.

**Самый простой путь к умной модели — блокнот [`colab/train_medium.ipynb`](colab/train_medium.ipynb).** Открой его в [Google Colab](https://colab.research.google.com/) (Файл → Загрузить блокнот), выбери бесплатную видеокарту T4 и запусти ячейки по порядку. Блокнот сам скачает русскую Википедию, обучит токенизатор, научит `medium` с нуля за несколько часов, дообучит на диалогах и выдаст `chat-q8.bin` для телефона. Прогресс хранится на Google Диске: если Colab отключится, обучение продолжится с места остановки.

Вручную на своём ПК:

```bash
pip install torch numpy
python3 tools/prepare.py pretrain мои_тексты/ --out-dir data --vocab 16384
python3 tools/train_torch.py --preset medium --data data/train.bin --val data/val.bin \
    --tokenizer data/tokenizer.bin --out models/base.bin --steps 20000 --batch 32 --compile
```

Потом скопируй `models/base.bin` на телефон и продолжай: дообучение `./corax finetune`, квантование и чат. Дообучать можно и на ПК: `python3 tools/train_torch.py --init models/base.bin --data data/sft --out models/chat.bin --steps 1000 --lr 1e-4`. Если обучение прервалось, добавь `--resume`, и оно продолжится с последнего сохранения.

`./corax` собирается и на обычном Linux или macOS (`make`), так что весь цикл можно отладить и на компьютере.

## Как сделать модель умнее

1. **Больше данных — главное.** Несколько гигабайт русского текста (книги, Википедия, статьи) дадут больше, чем любые настройки.
2. **Больше модель:** `small` → `medium`. Большую модель нужно кормить большим объёмом данных.
3. **Дольше обучение:** ориентир ~20 токенов на параметр (см. выше).
4. **Хорошее дообучение:** тысячи качественных диалогов в нужном стиле. Примеры из комплекта учат только представляться и самым простым ответам.
5. **Словарь 16384** для medium/large: короче последовательности, модель видит больше смысла за тот же контекст.

## Как устроено

```
текст → токенизатор BPE → эмбеддинги
      → N × [ RMSNorm → внимание (RoPE, GQA, причинная маска) → + остаток
              RMSNorm → SwiGLU (w2 · (silu(w1·x) ⊙ w3·x))     → + остаток ]
      → RMSNorm → умножение на эмбеддинги (связанные веса) → вероятности следующего токена
```

| Файл | Что внутри |
|---|---|
| `src/train.c` | обучение: прямой и обратный проход всех слоёв, AdamW, косинусный lr, чекпоинты |
| `src/gemm.c` | быстрое умножение матриц для обучения (векторное ядро 4×4, блоки под кеш) |
| `src/infer.c` | движок инференса: q8/q4/f32, NEON dotprod, внимание, сэмплирование |
| `src/quant.c` | квантование q8/q4 |
| `src/tokenizer.c` | BPE-токенизатор на C (совпадает с Python бит в бит) |
| `src/pool.c` | пул потоков: большие ядра, динамическая раздача |
| `src/main.c` | командная строка и чат с интерфейсом |
| `tools/tokenizer.py` | обучение токенизатора с нуля |
| `tools/prepare.py` | подготовка текстов и диалогов |
| `tools/train_torch.py` | обучение на ПК/GPU (PyTorch), тот же формат |
| `colab/train_medium.ipynb` | готовый блокнот Colab: Википедия → medium → чат |
| `scripts/` | установка в Termux, скачивание данных, полный цикл одной командой |
| `tests/` | сверка с PyTorch: градиенты, логиты, токенизатор |

**Формат модели** (`.bin`): заголовок 256 байт (размеры, тип квантования, сколько шагов обучено) → веса тензор за тензором → токенизатор вшит в конец. Один файл — и модель, и словарь.

### Проверка правильности

Обучение на C сверено с PyTorch: loss и **все градиенты** совпадают до ~1e-6, логиты инференса — до 1e-7 (f32). Токенизатор C выдаёт ровно те же токены, что Python. ARM-версия (NEON с dotprod и без) проверена в эмуляторе aarch64.

```bash
pip install torch numpy
python3 tests/test_grad.py                        # градиенты C == PyTorch
python3 tests/test_infer.py data/tokenizer.bin    # инференс f32/q8/q4 и токенизатор
```

## Если что-то пошло не так

| Проблема | Решение |
|---|---|
| `Illegal instruction` | старый процессор без dotprod: `make generic` |
| `Killed` при обучении | не хватает памяти: `--batch 2 --accum 4` или пресет поменьше |
| Медленно | открой Termux **на весь экран** (в плавающем окне или поверх видео Android отдаёт ядра другому приложению — скорость падает в 2–3 раза, программа об этом предупредит), `termux-wake-lock`, не сворачивай Termux (свёрнутый Android переводит на медленные ядра), охлаждение; для чата — `./corax bench -m ... --sweep` |
| «Модели … пока нет» | обучение не дошло до конца: запусти `bash scripts/quickstart.sh` ещё раз — продолжит с сохранения |
| Модель несёт чушь | мало обучения или данных: больше шагов, больше текста, проверь перплексию |
| Отвечает не по теме | нужно дообучение на диалогах (`finetune`); в чате та же `--system`, что в данных |
| `данных слишком мало` | текстов меньше, чем длина контекста: добавь данных или уменьши `--seq` |
| Кракозябры в выводе | шрифт Termux без нужных символов; проверь, что тексты в UTF-8 |
